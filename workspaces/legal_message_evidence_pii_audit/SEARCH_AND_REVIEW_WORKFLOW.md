# Search and Review Workflow

## Current State
OpenClaw has no purpose-built message search, chronology extraction, or exact quotation extraction tools designed for immutable legal evidence. Existing LLM workflows hallucinate quotations and fail to trace claims back to specific row hashes.

## Required Workflow
1. **Search Modes:**
   - **Exact:** Word/phrase matches, spelling variants.
   - **Semantic/Concept:** "Threats", "Admissions", "Contradictions". Must be LLM-assisted on the *Tokenized* copy only.
   - **Faceted:** By sender, recipient token, date range, or thread.

2. **Contextual Retrieval:**
   - A hit on Message `N` must return `N-3` to `N+3` (configurable) to prevent silent omission of contrary context.
   - The original chronological sequence MUST be reconstructed from `message_sequence` or `message_timestamp_utc`.

3. **Safe Review Result Contract:**
   - **Search Query / Mode:** The parameters used.
   - **Tokenized Participant:** E.g., `[PERSON_A]` via `[PHONE_A2]`.
   - **Exact Quote:** Extracted strictly from `message_body_exact` using offsets, NOT generated by an LLM.
   - **Date and Time:** With timezone offset explicit.
   - **Endpoint Used:** Exactly which phone/number sent the message.
   - **Context:** Messages immediately before and after.
   - **Source Trace:** `source_message_id`, `source_artifact_id`, `message_body_hash`.
   - **Human Verification Status:** Checkbox or annotation field kept entirely separate from the immutable evidence.

## Attorney Review Detokenization
An authorized operator, using a secure GUI or isolated CLI utility, inputs the Safe Review Result (which contains tokens). The utility securely decrypts the mapping from the Legal Sealed Vault, swaps `[PERSON_A]` back to `John Doe`, and exports a PDF/Docx. The LLM NEVER sees the detokenized output.
