## 0. Cleanup Posture
**CLEANUP REMAINS BLOCKED.**
This map classifies dependency pressure to help understand ownership and risk. No file movements, deletions, or structural changes are permitted based on this document. Any proposed cleanup actions are strictly candidates awaiting future explicit authorization and validation.

## 1. Dependency Classification Buckets
References identified in the File Path Dependency Scan are classified into the following buckets:
- **Active Dependency Owner:** Scripts, sync tools, or processes that actively rely on these paths.
- **Historical / Archive Reference:** Old logs, completed polish loop tasks, or deprecated notes that happen to contain the string.
- **Generated-Output Reference:** Files that are automatically generated by the system (e.g., reports, markdown indexes) rather than authored source truth.
- **Source-Authority Reference:** Canonical documentation or active planning packets that mention these surfaces.
- **Safe Candidate After Validation:** Areas that appear to be generated noise or stale, but still require a strict rollback/validation plan before any move.
- **Unsafe To Move:** Core dependencies, active sync scripts, and structural boundaries that will break the system if touched now.
- **Unknown / Manual Review:** Private roots or areas with insufficient context where making assumptions is dangerous.

## 3. Required Proof Before Cleanup
Before any future move, rename, or delete operation can occur:
1. **Clean Path-Dependency Scan:** A fresh run of `scripts/file_path_dependency_scan.py` must show zero active dependencies targeting the file/folder.
2. **Archive/Rollback Plan:** Deletions require an explicit, proven rollback strategy.
3. **No Private-Root Traversal:** The operation must provably avoid `.google-secrets`, `OpenClawLegalPrivate`, and other defined private roots.
4. **Targeted Validation:** Test suites (e.g., `pytest tests/test_mac_watch_markdown_index.py`, receipt checks) must pass before and after the operation.
