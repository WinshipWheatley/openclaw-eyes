# Dependency Hygiene

This document defines the architectural boundaries and import rules for the OpenClaw stack. These rules exist to prevent circular dependencies, reduce "heavy brain" sprawl, and ensure deterministic behavior.

## 1. The Utility Core (Decision-Free Layer)

Decision-free utilities MUST NOT import from "Brain" or "Manager" modules. They should be lightweight and safe to import from anywhere in the stack.

| Module | Responsibility | Rule |
| :--- | :--- | :--- |
| `chief_env.py` | `.chief.env` loading | AUTHORITATIVE for environment variables. |
| `cassandra_mode.py` | Global mode state (`focus`, `social`) | AUTHORITATIVE for mode-lock file paths and checks. |
| `chief_file_io.py` | Centralized JSON/MD operations | Decision-free writing to Vault and Logs. |
| `chief_output_utils.py`| TTS cleaning and text normalization | Pure string manipulation only. |

## 2. Brain vs. Reporter Boundaries

- **Reporters** (`chief_ops_reporter.py`, `chief_reporter_brain.py`): Should focus on deterministic synthesis of raw logs/state into markdown artifacts.
- **Brains** (`cassandra_briefing_brain.py`): Should focus on LLM orchestration and high-level logic. Brains consume artifacts generated by Reporters; they should NOT own raw parsing logic for source files.

## 3. Circular Dependency Prevention

Circular imports (A imports B, B imports A) are strictly prohibited.

- **Prefer Extraction**: If two brains need a shared logic or constant, move that logic to a new module in the Utility Core.
- **Local Imports**: Use local imports (inside a function) ONLY as a temporary measure during a refactor or for extremely rare, non-critical paths.
- **Pull Boundary**: Prefer a "Pull" model (Brain pulls data from an artifact) over a "Push" model (Orchestrator pushes data into a Brain) to decouple the layers.

## 4. Path Management

- **Authoritative Constants**: Paths to shared state files or Vault artifacts MUST be defined as constants in the module that owns the logic (e.g., `chief_ops_reporter.py` owns the path to `Ops Actions.md`).
- **No Shadowing**: Do not define the same path constant in multiple brain modules. Import the authoritative constant instead.

## 5. Execution vs. Transport

- **No Decisions in Transport**: Modules responsible for delivery (`cassandra_sender.py`, `cassandra_voice.py`) must NOT make logical decisions about whether to send a message. All gating (focus mode, approval check) must happen in the Brain/Scheduler layer BEFORE calling the transport module.

## 6. Hash-Locked Installs

- `requirements.lock` is the supply-chain-hardened install surface for the tracked Python requirement inputs.
- Install from it with hash verification enabled:

```bash
python -m pip install --require-hashes -r requirements.lock
```

- Regenerate it only from the existing requirement inputs and the current resolved environment, using hash generation enabled. Do not silently upgrade or downgrade dependency versions during lock refreshes.
