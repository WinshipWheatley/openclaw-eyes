# Operator Ship Metaphor Map

The Winship Operator Ship metaphor is a product-world model, not a literal ship game. It gives Operator Harness / Mission Control a personal, elegant, navigable structure for modes, authority, and state.

## Helm

Operator Harness meaning:
Current command, next safe action, approval, defer/block choice, and immediate steering.

Likely data/workflow surfaces:
Active workflow state, proposed action, approval request, risk reason codes, evidence summary, last safe checkpoint.

Possible widgets:
Current command card, approval card, next safe action, blocked/defer controls, evidence basis, confidence with reasons.

Safety/authority boundaries:
The Helm cannot imply hidden AI authority. Consequence-bearing actions require explicit operator approval and exact evidence/state version.

Visual/taste notes:
Focused and calm. Avoid gimmicky ship wheels. Use command clarity, light, and placement rather than nautical props.

## Bridge / Captain's View

Operator Harness meaning:
Ambient Watch Mode and the main window into the current world, port, route, or context.

Likely data/workflow surfaces:
Watch status, active context, freshness pulse, open-channel state, high-level blocked/review counts, local-only status.

Possible widgets:
Small VU/signal/evidence meter, watch pulse, current context chip, freshness note, next safe action teaser.

Safety/authority boundaries:
Watching is not acting. The Bridge should never imply autonomous mutation or surveillance beyond approved/local surfaces.

Visual/taste notes:
Annapolis-inspired marina, future port, calm water, warm dock lights, blue/violet night, hopeful horizon.

## Captain's Quarters

Operator Harness meaning:
Private planning, reflection, goals, briefs, operator preferences, and personal continuity.

Likely data/workflow surfaces:
Daily brief, priorities, goals, reflections, planning notes, personal state, operator-only context.

Possible widgets:
Brief card, priority stack, reflection note, goal progress, private reminder, tomorrow/next-week preview.

Safety/authority boundaries:
Private context must remain local/sensitive-aware. It should not become hidden authority for external action.

Visual/taste notes:
Quiet, personal, warm, and composed. More intimate than the Bridge, but not sentimental or cute.

## Chart Room

Operator Harness meaning:
Source registry, evidence map, freshness, unknowns, contradictions, launch packet routing, and auditability.

Likely data/workflow surfaces:
Evidence refs, source manifests, trace refs, freshness markers, unknown states, blocked reasons, versioned packet refs.

Possible widgets:
Source card, freshness badge, unknown-zone marker, contradiction card, route trace, packet readiness card.

Safety/authority boundaries:
Evidence maps cannot invent certainty. Claims must stay tied to sources, versions, and authority basis.

Visual/taste notes:
Charts, route lines, source markers, calm table light, and restricted waters. Avoid conspiracy-board clutter.

## Engine Room

Operator Harness meaning:
Runtime health, agents, queues, local models, disk/storage, sync state, and system capacity.

Likely data/workflow surfaces:
Agent status, task queues, model lanes, health checks, sync results, disk usage, service state snapshots.

Possible widgets:
Queue lane card, model lane meter, agent/crew status strip, sync pulse, disk/storage gauge, blocked process marker.

Safety/authority boundaries:
Viewing system health is not permission to restart services, mutate runtime, or self-heal without approval.

Visual/taste notes:
Mechanical but restrained. Warm amber indicators and clear channels. Avoid overheated sci-fi machinery.

## Cargo Hold

Operator Harness meaning:
Files, archives, storage, backups, source staging, ingestion candidates, and cleanup candidates.

Likely data/workflow surfaces:
File manifests, backup refs, storage zones, staging packets, unsupported-file paths, retention/cleanup candidates.

Possible widgets:
Storage manifest, backup status, staging card, local-only hold marker, cleanup candidate list, unsupported item card.

Safety/authority boundaries:
No deletion, cleanup, ingestion, sync, or movement without explicit authority. Sensitive holds must be clearly marked.

Visual/taste notes:
Orderly protected storage. Holds and crates as structure, not cartoon cargo.

## Radio Room

Operator Harness meaning:
Communications, drafts, mail, Telegram, contacts, inbound signals, outbound approval, and channel routing.

Likely data/workflow surfaces:
Drafts, contact refs, channel state, unread summaries, send approvals, blocked outbound items, communication traces.

Possible widgets:
Draft approval card, contact verification card, channel selector, inbound signal meter, blocked send reason.

Safety/authority boundaries:
No auto-send implication. Drafting, sending, contact lookup, and private message use must respect policy and approval.

Visual/taste notes:
Small signal lights, calm radio discipline, clear channel routing. Avoid chat-app clutter.

## Treasury / Purser's Office

Operator Harness meaning:
Invoices, receivables, obligations, ledger state, reconciliation, CPA readiness, and finance review.

Likely data/workflow surfaces:
Invoice refs, receivable status, bank/ledger reconciliation reports, obligations, CPA review markers, approvals.

Possible widgets:
Receivable card, obligation card, reconciliation result, mismatch reason, approval gate, CPA readiness note.

Safety/authority boundaries:
Never imply paid/posted/final financial truth without durable state and approval. Writes remain gated and idempotent.

Visual/taste notes:
Composed, precise, ledger-like without finance cliches. Avoid stock-trading or money-glow visuals.

## Studio Bay / Workshop

Operator Harness meaning:
Music, video, client projects, creative production, delivery packets, and project workflow lanes.

Likely data/workflow surfaces:
Project state, asset refs, version refs, delivery checklist, client approval, creative milestones, blocked dependencies.

Possible widgets:
Project card, asset readiness, delivery packet, milestone marker, client approval state, blocked dependency.

Safety/authority boundaries:
Client/private material remains protected. Delivery and external communication require explicit approval where consequential.

Visual/taste notes:
Studio-born but integrated into the ship. Tactile, capable, serious, and alive without imitating a DAW.

## Ports

Operator Harness meaning:
Workflows, clients, companies, projects, domains, life contexts, and launch destinations.

Likely data/workflow surfaces:
Context registry, launch packets, role maps, company/project boundaries, risk classes, active route state.

Possible widgets:
Port card, route preview, context selector, risk marker, launch packet readiness, local-only boundary note.

Safety/authority boundaries:
Ports must not cross-contaminate data or config. Company/client/domain context boundaries must stay explicit.

Visual/taste notes:
Hopeful map of contexts and routes. Avoid pirate maps, military campaign maps, and literal game navigation.
