# Mode Directions

## Spatial Compatibility Doctrine

Visual modes should be compatible with future spatial places without forcing the current 2D desktop app into literal spatial navigation. Each mode should preserve a clear work boundary, authority scope, evidence expectation, and blocked-state language so it could later become a place such as a dock, bridge, helm, chart room, engine room, cargo hold, radio room, treasury, studio bay, captain's quarters, port, or client site.

The modes should also train correct real-world work organization. Evidence should feel like it belongs in the Chart Room, runtime health in the Engine Room, money work in the Treasury / Purser's Office, communications in the Radio Room, creative production in the Studio Bay / Workshop, private planning in Captain's Quarters, and current decision authority at the Helm. Context switches should feel explicit, not like accidental tab chaos.

## Bridge / Captain's View

Visual scene:
A calm late-night bridge window looking out over an Annapolis-inspired marina, future port, or coastal horizon. The scene is sharp and ambient when idle, with warm dock lights, blue/violet night atmosphere, quiet water, and a sense of place.

Operator state:
Ambient Watch Mode. The system is awake, local-first, and monitoring without acting.

Widgets:
Small watch pulse, source freshness, next safe action, blocked item count, and one compact VU/signal/evidence meter.

Avoid:
Dashboard grid as the main concept, cockpit clutter, surveillance wall, dystopian harbor, pirate or naval costume.

## Helm

Visual scene:
A focused command surface layered over the bridge view. The Helm is current command, next safe action, and approval. It should feel precise and consequence-aware.

Operator state:
The operator is deciding, approving, deferring, or steering the next workflow step.

Widgets:
Approval card, current command, proposed action, evidence basis, risk reason codes, confirm/defer/block state.

Avoid:
Gimmicky ship wheel, fake autonomy, dramatic red alert, hidden authority, vague "AI recommends" cards.

## Chart Room

Visual scene:
A quiet evidence room with chart tables, route maps, source trails, freshness markers, unknown zones, and inspectable cards.

Operator state:
Source registry, evidence map, freshness review, unknowns, contradiction detection, and launch packet preparation.

Widgets:
Evidence cards, source refs, freshness badges, unknown/blocked reasons, route trace, confidence with reasons.

Avoid:
Readable private documents, conspiracy-board clutter, fake legal/finance screenshots, decorative maps without state meaning.

## Engine Room

Visual scene:
A restrained system-health layer: channels, meters, local model lanes, task queues, sync status, disk/storage health, and agent/crew states.

Operator state:
Runtime/system/agents/queues are being observed. Work can be routed or blocked, but runtime mutation is not implied by the visual.

Widgets:
Agent lane status, queue state, model lane health, sync pulse, disk/storage indicators, blocked process card.

Avoid:
Overheated machine-room drama, code rain, "AI swarm" visuals, hidden self-repair implication, service-control authority.

## Cargo Hold

Visual scene:
Protected storage below deck: organized holds, crates, shelves, archives, staging zones, backups, and local-only material boundaries.

Operator state:
Files, archives, backups, source staging, ingestion candidates, and cleanup candidates are visible but protected.

Widgets:
Storage card, staging manifest, backup status, local-only warning, retention/cleanup candidate, unsupported-file path.

Avoid:
Raw private screenshots, messy file pile, deletion theater, cloud-sync implication, unsafe ingestion visuals.

## Radio Room

Visual scene:
A small communication station with signal lights, draft queue, contact routes, message channels, and calm outbound/inbound state.

Operator state:
Communications/mail/Telegram/contacts are being reviewed, drafted, routed, or held for approval.

Widgets:
Draft card, contact verification, outbound approval, unread signal, blocked send state, channel selector.

Avoid:
Auto-send implication, private message content, social feed clutter, chatbot persona front-and-center.

## Treasury / Purser's Office

Visual scene:
A composed financial office aboard the ship: ledger maps, receivables lanes, obligations, invoice packets, cash-flow routes, and CPA-readiness records.

Operator state:
Receivables, obligations, ledger/invoice reconciliation, CPA review, and approval-gated financial consequence.

Widgets:
Receivable state, invoice evidence, obligation card, reconciliation result, approval gate, CPA review marker, mismatch reason.

Avoid:
Real financial data, stock-trading UI, money cliches, "AI accountant" autonomy, auto-pay/post implication.

## Studio Bay / Workshop

Visual scene:
A creative work bay integrated into the ship: music, video, client projects, gear cues, project lanes, and delivery packets.

Operator state:
Music/video/client workflows are staged, reviewed, routed, or prepared for delivery.

Widgets:
Project card, asset readiness, client approval state, delivery packet, creative milestone, blocked dependency.

Avoid:
Busy DAW imitation, brand/logo clutter, whimsical maker-space slop, implied client/private data exposure.

## Ports

Visual scene:
A navigable map of ports, routes, and contexts. Ports represent workflows, clients, companies, projects, and life contexts.

Operator state:
The operator is choosing where to go, what context is active, and what route or launch packet should open next.

Widgets:
Port card, route preview, active context, risk class, local-only boundary, next safe launch packet.

Avoid:
Literal game map, pirate map, military campaign map, one-size-fits-all workflow, cross-company data contamination.
