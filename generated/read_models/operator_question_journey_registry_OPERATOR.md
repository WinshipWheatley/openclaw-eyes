# Operator Question Journey Registry v0

Status:
- Deterministic metadata-only registry.
- Bounded operator-provided context only; no broad private chat ingestion.

## Why Questions Matter
- They expose confusion points and missing affordances.
- They correct system framing before it hardens into UI or package contracts.
- They identify taste constraints and workflow friction that polished summaries may erase.
- They can become doctrine candidates, but they are not promoted truth until source/proof/read-model criteria are met.

## Captured Journeys
- `check_engine_light_visibility`: question / promoted -> Check Engine must be a visible helm-level health light when active, not only a detail row.
- `helm_clutter_objection`: objection / promoted -> The helm should answer mode, health, active mission, attention, next safe move, blocks, and proof access without becoming a card wall.
- `nested_lanes_backend_not_ui_tree`: correction / promoted -> Nested-lane topology belongs mostly in deterministic read-models; the helm should not default to deep tree navigation.
- `actor_model_agent_character_split`: correction / promoted -> A package chooses the model actor, attaches the agent character, and defines context, tools, clearance, steps, stops, and receipts before any future launch.
- `deterministic_package_generation`: doctrine_candidate / promoted -> Package compiler maturity path: LM prose may help wording, but deterministic contract fields decide authority and validity.
- `tell_system_whats_missing_button`: question / candidate -> Tell System What's Missing is a future-gated capture/package path that records missing-memory posture and requests safe discovery/classification.
- `check_transmission_not_check_engine`: correction / promoted -> Check Transmission owns state-transfer faults; Check Engine should not duplicate bridge faults as a catchall.
- `doom_space_station_visual_metaphor`: taste_signal / needs_source_artifact -> Mission Control should feel like a helm/base where the operator orients, stages packages, upgrades/prepares, and enters worlds.
- `operator_system_above_operating_systems`: promoted_doctrine / promoted -> OpenClaw is the helm/router/package layer that lets the operator navigate and control underlying workbenches safely.
- `avoid_developer_tool_power_user_requirement`: objection / promoted -> Mission Control should hide workbench complexity behind deterministic package routing and proof/receipt expectations.
- `prior_question_answer_source_artifacts_missing`: known_unknown / needs_source_artifact -> Question journeys from prior discussions need an approved source artifact or metadata-only capture packet before promotion.

- do not claim broad private chat history was ingested.
- do not claim the Mac UI has implemented these journeys.

- do not claim live model/tool/agent/workbench authority.
- do not treat operator memory as canonical truth without a receipt/source path.
