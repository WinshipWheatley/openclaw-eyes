# Operator Hard-Steer Field Kit

This folder is a high-signal field kit for the operator to rapidly orient and "hard-steer" AI workers. It distills the complex Documentation Waterfall into concise, actionable guides.

## When to use these files
Attach or reference these files when a worker (Gemini or Codex):
- Drifts from the core mission or taste.
- Takes timid "baby steps" when the road is visible.
- Overbuilds doctrine instead of implementing clear next steps.
- Ignores the North Star or current repository truth.
- Assumes hidden execution authority.

## File Selection Guide
- **00_READ_ME_FIRST.md**: Initial worker orientation.
- **01_NORTH_STAR_AND_TASTE.md**: When the worker loses the "why" or implementation quality drops.
- **04_ANTI_DRIFT_RULES.md**: To stop slop, baby steps, and generic doctrine bloat.
- **05_CODEX_BUILD_RULES.md**: For Codex implementation, diff, and test tasks.
- **06_GEMINI_AUDIT_RULES.md**: For Gemini planning, research, and synthesis tasks.
- **07_AUTHORITY_AND_COVENANT_RULES.md**: When a worker assumes authority or forgets the sacred pause.

3. Packet 07 rails (`docs/planning/project_packets/07_.../24_files/`).
4. Active handoff (`00_ACTIVE_HANDOFF.md`).
5. Built proof (Committed code, receipts, and tests).
